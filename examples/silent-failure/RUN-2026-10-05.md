## What this does and does not show

- **Claude was right 12/12 times without the mod.** On these inputs, the current model reads a buried failure on its own, even when exit 0 and a green last line say otherwise. We tried to make it miss, and could not.
- So the claim this repo makes is **not** "Claude misses failures without this mod". The claim is narrower and checkable:
  1. **You** see it. The status line and transcript line appear whether or not you were reading the tool output.
  2. **It is recorded.** `/silent-failure last` keeps the evidence across reloads and sessions.
  3. **Claude is told explicitly**, in the same place a PostToolUse hook's context goes, instead of being trusted to notice.
  4. **Masking is named.** `| tail`, `|| true` and `; exit 0` are called out, which the output alone never says.

**Falsifiable takeaway:** if you find an input where the mod flags a failure that the output does not contain, or misses one that a `high` rule should catch, that is a bug. Open an issue with the command and its output.

---

## False positives seen while building this repo

The mod scans text, not meaning. During this session it fired twice on commands whose output **quoted** failure lines, such as a script printing the A/B results above (`HOLD: … 1 failed, 46 passed`). Both were correct readings of the text and wrong readings of intent.

Workarounds today: `/silent-failure off` while you inspect logs, or ignore the line. A viewer allowlist (`cat`, `grep`, `git log`, `jq` …) is on the [roadmap](../../docs/ROADMAP.md).
